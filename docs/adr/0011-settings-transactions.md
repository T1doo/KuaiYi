# 0011：不可变设置草稿与可恢复秘密引用事务

状态：实现候选；可移植路径已验证，Windows 实机未验证。

P0 平台门槛受阻时，按明确授权先推进独立 P1 配置部分。Core 负责不可变定义、校验、草稿、文件和事务，Windows 负责当前用户 DPAPI/ACL，App 只处理表单和 RuntimeGate。现有 Provider 及 OLE 架构保留。

提交前串行获取可跨进程的事务锁，再由配置锁和主/备份摘要校验草稿版本。同目录临时文件刷新后才替换；配置 `writeId` 唯一标识实际提交。UI 等待取消不代替事务结果；提交后核对磁盘并完成必要撤销，失败则保留 journal。旧原子配置、有效备份、未知格式和不可证明归属数据均不提前删除。

配置、备份和 journal 只包含秘密引用。新密文先保存；提交后才持久撤销/删除明确清除的秘密。替换时保留备份所需旧密文，后续完整请求引用回收由 P4 连接；无法证明事务时阻止继续，不猜测旧密钥应删除或重新启用。

schema1 为当前完整配置定义；schema0 是明确、有限、未发行的初始布局草稿测试契约。未知版本或无法识别的旧迁移只读。结构、默认值、数值范围和枚举由定义导出，跨字段语义集中验证。实例不保存 Activation、选区或翻译历史。

文件替换与 Flush 的平台合同见 settings-review.md 的官方链接。Linux 的实际文件/进程终止和 AES-GCM 合成测试不能证明 Windows DPAPI、ACL、WPF、硬件断电或磁盘写满行为。P0/P1 退出门槛未改变。

新引用采用key/随机GUID的不可变标识，避免覆盖旧密钥；规格示例的逻辑profile路径不是本切片的磁盘文件名。完整API配置导入及逻辑引用兼容不在本次交付范围，R05仍未整体完成。

监督复核修正：恢复选择与其显示草稿由同一个所有者持有，备份/默认分支独立保留，原保存真实返回前锁定来源；非Int32 schema是损坏而未知合法Int32保全只读。共享秘密引用合法，退休及已提交journal恢复均扣除已保存配置仍使用的引用；最后引用移除才撤销。详见settings-recovery-review.md，Windows实机门槛不改变。

后续绑定修正：物理秘密退休与profile旧绑定失效分别建模。运行时当前绑定有内存GUID，旧引用清除/替换或配置删除只取消对应身份，不全局Disable或吊销B共享密文。新schema2 journal保存绑定通知，所有订阅者均尝试接收；异常保留journal，证明提交后可重复通知。schema1兼容读取且仅据已知旧Effective推导变更，不伪造未知历史；未来journal保全。详见settings-bindings-review.md，P4正式调度及Windows实机仍未交付/未测。
