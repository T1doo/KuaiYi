# Evidence for cancellation before Ready

With the corrected public source identity, the Windows probe observed matching receiver QueryEnd with COPY, actual Drop and source GetData blocking, then cancellation, replacement and close. The application exited 0. The outer reader still rejected its receipt. Its checkpoint contained extra owned receivers cancelled during ParentHelloRead; the previous pass validator allowed only ParentRun cancellation. The checkpoint alone does not establish why those starts were cancelled or certify whole-owner finalization.

On/Off, moving and close may legitimately overlap an owned handshake. Every attempt remains in the receipt, including attempts that never became Ready. The verifier must distinguish an explicit parent revocation from a startup timeout, internally failed control or a failure followed by a later Off command. It must not remove owners, stop legal replacement to obtain a fixed count, or merely expand the allowed stage list.

The CI-only parent now freezes its first explicit revoke evidence before its actual Cancel call: fixed reason, original Run pending, no existing StartupFailure, and both internal stop and the caller token still fresh. These values are never filled in by finalization. Client observations retain whether Ready or registration was actually reached and whether startup/watchdog expiry occurred. Creation records retain actual wanted/lease-current observations, in addition to existing prior-owner settlement evidence.

A pass receipt still requires every original Run/control/read and owner finalization, exact created/prior/ready association, register/revoke cleanup, separate native source/receiver identities and both real GetData scenarios. Every Ready owner additionally requires its own unique Ready binding and original registrar Task completion. A cancelled pre-registration owner is accepted only with explicit prior revoke evidence, no deadline/control/register start, an original Canceled Run, a verified owned process exit and complete original cleanup. Its never-started registrar has UNKNOWN original Task state and zero thread identities; UNKNOWN is not interpreted as a completed registration. Any Ready/event claim for that owner is rejected. The outer summary also requires at least three verified Ready owners.

Only after all pass checks succeed does projection label an owner Ready or CancelledBeforeRegistration. Failed receipts retain UNKNOWN. Existing unexpected EOF, wrong identity, unconfirmed cleanup and private-content rejection tests remain. Additional regressions use an actual owned child held before Hello response, compare explicit revocation with the actual startup deadline, and reject late/backfilled revoke, pending work, missing exit, registration/control starts and false Ready claims.

Receipt rejection now retains a fixed whitelisted rule alongside the original failure stage/code. No arbitrary exception message is serialized. Native observations remain OBSERVED until the complete final receipt is validated. Physical E06 and Windows 11 acceptance still require separate execution evidence.
