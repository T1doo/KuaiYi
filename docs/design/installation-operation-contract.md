# 单一安装操作编排合同（限定内部入口）

依据SPEC13.4，接续52b1130产品/1b6a914证据。复用同原DeploymentScope的Ticket/Before/G/B/Prepared/三资源提交，以及原NewSession→Compensation→RestoredSession；不新增恢复算法/磁盘locator/新journal，不接真实安装器命令、用户注册或Windows验收。

## 原owner与观察结果

一个InstallationOperation实例只Begin一次，先发布原编排Task与结果TCS，再开始任何IO；原Scope、registry owner、controller创建Task及新旧session/compensation始终归该实例持有。只把原Scope精确Committed接入新受控会话，不凭历史文件重新签发。controller工厂在原Task内逐次调用且每次独立fresh；不共享失败controller或launch。

结果Completion为不可变的阶段结果，不声称所有进程已退出：NewVersionReady/PreviousVersionReady只由对应原session.Ready成功签发，绑定operation、generation、launch、proof。原编排Task随后继续join该session.Completion，后续退出/取消/清理错误在原结算结果中保留；不得回写健康结果或自动再次补偿。CleanupConfirmed另核全部原Scope/session/compensation/controller lease与原Task，live READY明确不是清理完成。未知始终静态保留同operation及其所有原owner，不提供fresh重试、resume或清unknown API。

## 唯一路径及终态

1. 原Scope Acquire→Before→G→B→Prepared→CommitPrepared，异常按实际已开始阶段请求原Abort并join原finalization，原正文/结算错分别保全。Refused/Aborted*且全部原cleanup确认才是NotCommitted；CommittedReceiptUncertain/Unconfirmed或关闭未知一律Unconfirmed，不调用controller工厂。
2. 精确Committed并且取消尚未请求才创建新controller、调用原BeginCommittedSession。新READY成功为NewVersionReady；用原Ready成功资格而非Task.WhenAny赢家身份，也不在canonical READY成功后以晚到取消倒写失败。原session.Completion若无READY，仅RollbackRequired且原角色/原Task结算与原execution仍held时进入原补偿；ActivationBlocked为CommittedNotReady，Unconfirmed为Unconfirmed。原外部/未知owner不收养、不kill，不人工Start一个角色来制造回滚资格。
3. 新会话失败后BeginCompensation只用同原Session/原controller/原execution。该段为本次安装失败的既定反向清理，以CancellationToken.None结算：前向取消触发后仍须尝试已授权恢复，而不是拿已取消token直接拒绝清理；不改变原Compensation API的Closing/unknown合同，不新增二次恢复/取消入口。任意partial/foreign/关闭或Move未知终态Unconfirmed，零旧版启动，无重放。
4. Compensated只记“已恢复历史”。Before.current为空为RestoredNoPrevious，零旧controller工厂/旧session/虚构READY。存在旧G但前向取消已请求，为RestoredPreviousNotReady，不自动重启旧程序。否则创建独立旧controller并走原BeginRestoredSession；原旧READY成功为PreviousVersionReady。旧会话确定Failed/ActivationBlocked为RestoredPreviousNotReady；旧会话Unconfirmed/关闭未知为Unconfirmed。无第二次补偿、无恢复旧Prepared/失败launch。
5. 提交Closing后的取消由原Scope照常结算，若最终Committed但本操作尚未启动新版，终态CommittedNotReady；没有原execution就没有补偿资格，不能假报已恢复。该状态及初始外部owner竞争必须明确，不把内部编排签为完整安装成功。补偿后取消边界同第4项：恢复已完成仍不代表旧版健康。

公开内部结果只含实际阶段/原结果及已签READY，错误列表保单一原异常身份、多错保全部leaf，不用Task.WhenAll抛出的单错代表完整失败。状态包括NotCommitted、CommittedNotReady、NewVersionReady、RestoredNoPrevious、RestoredPreviousNotReady、PreviousVersionReady、Unconfirmed；阶段快照另标Preparing/Publishing/Committed/NewSession/Compensating/Restored/PreviousSession/ResultPublished。先发布结果时不得新增会失败的部署IO；此后只join原会话结算任务，结算错单独保留。

## 最小源码与验收

新增一个Core操作owner及结果/阶段类型，借已有Core registry接口和controller工厂，不包裹独立安装入口拿多重锁；原DeploymentSession仅补内存OriginalWorkPending观察（与既有restored同合同）。现有原scope/commit/补偿/旧session的写入与归档算法不变。测试抽取已有Sources fixture以走实际prepare→commit，不再手造已提交tree。

必要合成链：新版READY与原生命周期分离；新版失败→恢复→旧版READY；首次安装失败恢复空；提交前取消/部分写未知；提交后取消或foreign执行owner拒绝启动且无假补偿；补偿unknown不创旧controller；旧版失败与已恢复区分；原协议cleanup held时不提前补偿/退出；取消触发恢复但不自动重启旧版；READY后取消只记后续原结算；原多错保全。只跑新编排矩阵与少量旧共享helper代表链，不叠加266或旧204数字。不提高250/600ms/原会话预算，不真实模型调用。

真实Windows/medium/Explorer/浏览器/WPF、完整安装注册/卸载、三native DLL与完整self-contained runtime、实际旧版桌面健康/画质250600/完整P7仍未验；本片只对隔离文件根/fake registry/实际Start持有的合成stdio子进程作限定签收。

实施补充：迟到工厂原Task先join，取消复核后在同controller原serial内fresh-only封闭内存disposed状态，其任务预先登记；绝不走通用Dispose/Finalize其他角色。factory/unused-close异常永久controllerUnknown；Result Unconfirmed即使原资源已关闭仍保静态operation，清理完成不提升历史健康。独立旧Peer未知时内外fixture也保同Rig/Stop/root，不继续Dispose共享Stop。
