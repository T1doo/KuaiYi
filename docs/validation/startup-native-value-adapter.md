# Fixed current-user startup value adapter — source candidate only

SPEC8.2,13.4/P7-04 require optional current-user startup and withdrawal of only this product's registration. Before this candidate, Installer.Program constructed InstallationDeploymentRegistrySnapshot(new WindowsHostRegistrationStore()), whose runtime type supports Chrome/Edge publication but not IInstallationStartupRegistry. Therefore the existing original-installer qualified startup source, seven-prefix publication/compensation and same-session settings removal could not receive a production Run adapter.

The candidate adds WindowsStartupRegistrationStore and InstallationStartupRegistrySnapshot, plus a passive CreateWindows factory used by the exact original Program expression. The old Chrome/Edge-only constructor retains its interface and behaviour for existing users/tests; production receives the combined capability. Source-pins are still read and validated before platform-owner construction. This is not an authorization factory: only the original pinned installer still mints its in-memory StartupSources through the existing Core path.

The minimum contract is:

- Fixed HKCU Software\Microsoft\Windows\CurrentVersion\Run, exactly the KuaiYi named value, explicit64-bit view. Query uses KEY_QUERY_VALUE; mutation adds only KEY_SET_VALUE. No neighbouring/default value enumeration or mutation, key deletion, ACL/token/policy operation or alternate hive/path. A created shared key is retained. Compare/read/write is cooperative, not atomic CAS against another same-user writer.
- The original raw key owner exists before Open/Create, including partial acquisition then exception. Every access closes that exact handle using RegCloseKey's returned status; close failure retains it and blocks new access until exact original cleanup. Body+close errors are preserved in order, single original errors use existing EDI semantics.
- Bounded one-call8194-byte query; only canonical terminated UTF-16 REG_SZ becomes a supported value, with no environment expansion or repair. Other types, oversize and malformed strings become explicit unsupported observations. Expected and new values are validated. New commands over260 UTF-16 code units or unencodable strings are refused before any key open; no budget is enlarged. Missing-to-missing does not create a key, identical values do not rewrite; removal deletes only the exact named value.
- The combined owner pre-registers its task before any host/startup call, uses one pending operation/zero queue and refuses early close. Startup reads require the original host capture; writes require original preparation and no verification phase. Host and Run work share the same slot. Any explicit HostRegistrationConflictException, including one inside a body+close Aggregate, is sticky even if an external actor restores the prior value and the original handle later closes. Ordinary write-after-effect failure retains observable effect and existing reverse capability.
- Close independently joins/cleans the host and retained Run owners, collecting both errors. Core's original scope, before/owner/source checks, seven prefixes, startup-owner receipt and reverse order remain unchanged. No startup opt-in, arbitrary executable, new locator, trusted receipt or ordinary-Launcher authority is created.

Primary Windows contracts checked: [Run/RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys), [registry access rights](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-key-security-and-access-rights), [RegQueryValueExW termination and size](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regqueryvalueexw).
