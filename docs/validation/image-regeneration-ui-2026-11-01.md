- Original Discover/Start refusal could look like successful task completion when an earlier owner had CleanupPending. Regeneration now throws an unconfirmed-cleanup outcome at both refusal points, preserving that owner and faulted original task. No automatic retry, owner rebuild or cleanup of unknown workers occurs.
- A synchronous predecessor-cancellation callback can select another version and return before the OCR admission call returns. The UI correctly rejected continuation, but cleanup formerly matched the old ExpectedEpoch and left this just-admitted capability/vision/preview. Three actual red cases reproduced those retained outcomes (**3F**) before the fix; originals are retained.
- OcrOnlyCoordinator now provides optional out RequestIdentity correlation on successful Discover/Start; failure returns default. Old APIs delegate to the same original admission/body. This is cleanup correlation, never image/send authority. The UI captures the original owner, Task and full actual identity independently from the epoch permitted to continue. Even if continuation is rejected, it joins that original task and rejects only its completed source/settings/identity-matching result. Pending tasks report unknown; unrelated identities and unknown workers are not cleared. The original gate, approvals, source authority and password/secret path are not replaced.
- Finally releases this operation's completed OCR outcomes even when a version ABA prevents assigning a preview to the modal UI. Body errors and independent cleanup faults stay aggregated; an observer does not replace the faulted smartImageTask with a successful task.
