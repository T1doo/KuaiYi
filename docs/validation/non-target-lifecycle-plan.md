## Initial audit blocks and corrected offline verification

Independent source audit blocked initial `e8e04d991bd4764c47f1e2f70dd9ef72bd7c4009`: duplicate ParentSettled could pass, death observation relied only on timer cancellation, strong kill reused an idempotent no-op helper, and a late-start child could miss the previously requested first termination. Corrections: ParentSettled now requires the exact predecessor (FinalReleased for Normal, Parked for Watchdog), zero origin/elapsed and no duplicate. Strong death origin freezes before the Kill invocation; both original exit observations use the same shared absolute600ms post-await check. Startup origin now predates parent Start and handshake/ACK boundaries are independently checked. Strong kill requires a live held process and a successful actual Kill invocation; stage says TerminationRequested, not proof of termination cause. Gate requires this issued request plus actual exit confirmations, and rejects natural-zero parent exits in death cases.

Cancellation of a wait never erases this intent or the original task. An already exited process cannot produce strong-kill evidence; a failed attempt is not retried. This remains pure policy testing, not a Windows syscall observation.
