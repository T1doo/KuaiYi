This change prepares a finite Windows observation tool; it does not change the production animation, dispatch CI or produce new native images. Base revision is `0613fce78ead08897d4fe9a94d5a80e88fc35f62`, on `dev/p7-fixed-signoff`. Existing settings-navigation acceptance remains separate.

## Actual production path and narrow changes

`GrowthHarness --ci-overlay-stages EXISTING_EXCLUSIVE_OUTPUT` constructs the real `ShellWindow` with an owned settings coordinator, neutral synthetic Chinese text and `enableSelectionPlatform:false`. Bound Begin/Delta/Complete events enter the existing `ReceivePresentationAsync`; the original 50 ms text flush and `CompositionTarget.Rendering → OverlayFrames.Tick → ApplyOverlayFrame` retain the same HWND. Original toolbar Click handlers perform collapse/reopen. No harness loop calls Tick or sets window geometry. Programmatic Click is not physical input acceptance.

The only production additions are two readonly internal observations in `OverlayPresentation.cs`: the original `ShellCloseRequests.Current` task and whether `ApplyOverlayFrame` is currently active. Existing ownership, geometry, 220/180/70 ms timing, source/password/integrity, cancellation/isolation, 250/600 ms contracts and sending gates are unchanged. The fixture enables only its own synthetic presentation identity, never constructs a model request and does not alter real settings or system animation preferences. Installer pins remain Unavailable.

The tool runs nine stages twice: seed open, long-text height growth, close, reopen, close until an observed intermediate frame, reverse to open, close to compact, open until an observed intermediate frame, reverse to close. The first collection records timing without raster capture; the second records actual WPF content rasters. Stages/waiters are published before commands, bound to their exact original instance and cleared on retirement. A terminal state without observed changed intermediate geometry cannot pass. Expanded completion also requires a visible positive-size body, opacity at least .99 and the stage's flushed document marker. Marker presence is not a claim that its glyph is inside the current viewport.

## Evidence and cleanup ownership

Raw callbacks are retained, capped at 10,000; duplicate RenderingTime, reentrancy and Apply-in-progress observations are marked. Only the first stable observation for a RenderingTime contributes to stage coverage, so a preceding reentrant callback cannot consume it. QPC and RenderingTime regressions fail. Stable samples require the original HWND/anchor, native/model bounds equality, button/anchor equality, work-area containment and unchanged foreground. QPC frequency, command issuance, first changed geometry and per-stage eligible callback gaps are recorded; these are observed callback timings, not DWM presentation receipts or click-to-photon measurements.

Raster capture occurs at the observed WPF state using RenderTargetBitmap and Freeze; encoding/writing happens only after original driver/close/owned-state settlement. Each image retains before/after observations, actual dimensions and SHA256. `Stable` asserts only equal before/after Card/Native/Anchor/Hwnd; the full visual tree is not claimed to be an atomic snapshot. Direction, body width and scroll offset are recorded, not asserted as direction-freeze or reading-anchor acceptance. Bounds are 24 frames, 64 MiB reserved pixel storage, 4 million pixels per frame, 768 KiB per PNG, 8 MiB total PNG, and 16 MiB per JSON. There is no interpolated or retimed animation.

The original driver is published before dispatcher release. One close request retains the exact original close task and separately joins the original Closed observation. A completed close task alone cannot authorize cleanup. Body, close-task, Closed and cleanup failures remain separate. A 45-second driver deadline requests cancellation and records pending state; an elapsed-budget check also marks timeout. Unknown constructor/close/cleanup retains the owner, state and dispatcher. Only confirmed original close permits deleting the tool's own state directory. This tool does not itself create/terminate an external process; the future reviewed runner wrapper must retain and settle its original process and stdout/stderr operations within the existing 60-second bound. A successful internal task is not proof of OS process exit.
