## Completed functional increment

After a consumed image result, the old style route fell through to a text-session preview or the initial-image-only selector and was disabled. The new real image-session consumer edits only the next requested text preset. It binds the original retained VersionState/session/borrowed owner and selected version. It does not capture, read a key, write settings, send HTTP, cancel an admitted Job or change any previous version's settings/preset/plan.

Default regeneration uses the shown version's preset; a local override follows that image session across retained versions. Reset uses the **shown version**, not a silently changed global default. Explicit current-settings regeneration still uses the saved global choice. Image explain mode still forces Explain regardless of the text-preset override. Clear, source revocation and pruning the last retained session remove the override.

The original style button and session-style menu now show the next version/preset. Local metadata editing is available without opening image regeneration; labels say only the next text style changes, structured-image explanation remains Explain, and regeneration is still unopened. The actual image-generation qualification remains fixed false with no override. Old rendered result labels remain their original style.

A style revision invalidates pending confirmation and any older modal/OCR intent, including A→B→A choices. State/revisions and offer detachment happen before releasing that original approval. A launched request retains its immutable preset. One held-OCR regression verifies that changing next style does not cancel/rebuild the original owner, waits its settlement, releases its particular outcome and sends nothing under the stale style intent.
