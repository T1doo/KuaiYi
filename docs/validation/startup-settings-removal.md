# Qualified startup removal — original-session settlement

This remains internal B1 removal only. No real Run adapter, startup enablement, ordinary Launcher trust or production settings UI is enabled. Embedded pins remain Unavailable/null and public SettingsJson stays false-only. No Windows, model or CI acceptance is implied.

The original successful Installer/Operation/Scope and exact READY controller create the nonserializable owner. The original admission is borrowed, not reacquired. Settings reserve it before Settings.serial and secret-transaction.lock. The canonical schema-3 local intent is bound by Request, WriteId, BasisVersion and SHA256, at the fixed original data/config path. A separate original-controller binding precedes external effects. A file/receipt/PID cannot reconstruct an owner.

COMMIT_OK and ABORT_OK now observe only a durable decision. They do not archive the controller pending record or remove/retire local v3. A successful local save returns PublishedAwaitingOriginalControllerSettlement; the App may still be running. Published configuration is not rolled back. Every safety subscriber is notified, and necessary local secret revocation/cleanup continues with all original failures preserved. The App has no v3-deletion method. Unknown/partial local IO remains retained.

After local work, at most one bounded LOCAL_SETTLED notification carries the original Request, WriteId, canonical v3 digest, committed/aborted outcome, configuration version and local cleanup result. There is no response and no acknowledgement loop. Both ordinary response observation and notification observation are bounded, while their exact original tasks remain tracked. A timeout means unconfirmed, never cancellation/disposal or completion of those original tasks. Settled local protocol failure may close the UI without EXIT_READY; outstanding local IO still blocks cleanup.

The controller pre-registers its retirement task before any request. Retirement requires the actual original App exit, original OS wait and protocol-IO join references, original read completion, every original response/send/flush task, and confirmed original process-handle finalization. The private controller Role supplies that evidence; new completed tasks, disk state or a PID cannot substitute. For a bound intent, missing notice, mismatched binding, failed response or failed local cleanup returns/records unconfirmed with the original work and records held.

Bound-intent retirement uses separately owned original IO ledgers for installation metadata and data/config. It rechecks the live original scope, exact controller pending/binding/decision, canonical v3, configuration outcome/version and necessary secret-cleanup facts. It reads no plaintext secret. All those original reads and closes settle before the one-shot v3 move to startup-settled-<request>-<write>.json and the final controller pending-to-finished move. No failing resource cleanup follows those moves within the retirement task. Move uncertainty is not replayed. If a bounded observation expires with the original producer pending, admission is not closed underneath it; before Closing the owner is revoked, and after Closing only the already-owned finalization may settle. Outer session/execution cleanup remains a separate result and may still be unconfirmed.

A normal synthetic App exit now automatically converges to retirement. While the App remains alive, the explicit outcome stays pending and v3 remains. Original errors and unknown roots are retained; no existing test assertion or 250/600ms/source/password/integrity/cancel/send gate is relaxed. A's seven deployment effects and reverse compensation remain; this does not implement startup on/off cycles or full uninstall.
